# Shelf Bench architecture

This page describes the code as it is. Every claim points at a file and line. A claim marked
`UNVERIFIED` has no proof in this repo.

Bridge shorthand: `shelf-bridge <path>:<line>` means a file in the
[shelf-bridge](https://github.com/Ted2xmen/shelf-bridge) repo at the revision Shelf Bench pins
(`f815abd57072efef572f5244cee62b7ae1bd3866`, see `BenchCore/Package.swift:15`). The protocol is
described in [protocol v2](https://github.com/Ted2xmen/shelf-bridge/blob/main/docs/protocol/v2.md).

(`project.yml:1`).

(`scripts/gate.sh:55-59`).

## Entry point and scenes

`App/Sources/ShelfBenchApp.swift` holds the `@main` app and its delegate.

- One `Window` scene, id `main`, with a hidden title bar (`App/Sources/ShelfBenchApp.swift:9-14`).
- The File menu's New item is replaced by "New Session..." with Cmd-N. It is disabled when Bench's
  own tmux server could not be resolved, that is when tmux is not found
  (`App/Sources/ShelfBenchApp.swift:16-20`, `App/Sources/System/BenchServerRunner.swift:12-16`).
- A `Settings` scene with `SettingsView` (`App/Sources/ShelfBenchApp.swift:23`). It holds the
  appearance picker and two placeholder rows for Bridge (`App/Sources/Views/SettingsView.swift:10-28`).
- The saved appearance is applied before the first window draws
  (`App/Sources/ShelfBenchApp.swift:31-33`).
- After launch the model starts (`App/Sources/ShelfBenchApp.swift:35-42`).
- When Bench comes to the front it pings Bridge (`App/Sources/ShelfBenchApp.swift:48-50`,
  `App/Sources/Model/AppModel.swift:131`).
- Closing the last window quits the app (`App/Sources/ShelfBenchApp.swift:52`). Quitting closes
  every job view Bench opened (`App/Sources/ShelfBenchApp.swift:54-56`,
  `App/Sources/Model/AppModel.swift:135-139`).

### The `shelfbench://` URL

- `Info.plist` registers the `shelfbench` scheme in the Viewer role (`App/Info.plist:5-17`).
  project.yml merges it with the generated keys (`project.yml:47-49`).
- The delegate passes every opened URL to the model (`App/Sources/ShelfBenchApp.swift:44-46`).
- `BenchURL.jobID` accepts only `shelfbench://job/<id>` with one path part, no query, no fragment,
  and an id that passes Bridge's `JobID.isValid` (`BenchCore/Sources/BenchCore/BenchURL.swift:9-15`).
- The model selects the job (preferring its Needs you copy) and activates the app
  (`App/Sources/Model/AppModel.swift:52-56`, `App/Sources/Model/AppModel.swift:165-169`).
- Who opens it: shelf-bridge's notification click, when Shelf Bench is installed
  (shelf-bridge `Sources/ShelfBridgeCore/Notices.swift:76-95`). See
  [protocol v2, notification click](https://github.com/Ted2xmen/shelf-bridge/blob/main/docs/protocol/v2.md#14-notification-click).

## AppModel

`AppModel` is the one `@Observable` model, a main-actor singleton
(`App/Sources/Model/AppModel.swift:7-13`). It holds what was heard and chosen; words and grouping
come from BenchCore (`App/Sources/Model/AppModel.swift:86-103`). It:

- resolves Bridge's tmux and Bench's own tmux server once (`App/Sources/Model/AppModel.swift:26-29`);
- starts the status feed, a 1 s clock tick and a 2 s timer that probes job views and polls Bench
  sessions (`App/Sources/Model/AppModel.swift:107-129`);
- keeps the newest status reading (`App/Sources/Model/AppModel.swift:146-155`);
- owns the life of job views: open on select, close on deselect, on quit, and when a view stops
  showing its job (`App/Sources/Model/AppModel.swift:171-218`);
- polls, starts, ends and restarts Bench sessions (`App/Sources/Model/AppModel.swift:220-296`);
- sets the Dock badge to the count of asking jobs and sessions
  (`App/Sources/Model/AppModel.swift:157-161`, `BenchCore/Sources/BenchCore/Sidebar.swift:108-109`).

## Watching shelf-bridge

Bench only listens and reads. The only thing it posts is the ping
(`App/Sources/System/StatusFeed.swift:41-44`; no other `postNotificationName` in `App/` or
`BenchCore/Sources/`).

### Three inputs

1. **Status notification.** Bench observes `dev.ted2xmen.shelf-bridge.status` with any object and
   reads the `json` string from `userInfo` (`App/Sources/System/StatusFeed.swift:24-31`). Bridge posts it with `["v": 2, "json": ...]` and writes the same JSON to `heartbeat.json`
   (shelf-bridge `Sources/ShelfBridgeCore/ShelfChannel.swift:64-65`). See
   [protocol v2, status](https://github.com/Ted2xmen/shelf-bridge/blob/main/docs/protocol/v2.md#7-status).
2. **`heartbeat.json`.** Read at launch and then every 5 s, off the main thread
   (`App/Sources/System/StatusFeed.swift:10`, `App/Sources/System/StatusFeed.swift:32-36`,
   `App/Sources/System/StatusFeed.swift:46-52`). The path is Bridge's state folder plus
   `heartbeat.json` (`App/Sources/System/Files.swift:26`), which is
   `~/Library/Application Support/shelf-bridge/` (shelf-bridge `Sources/ShelfBridgeCore/Paths.swift:16`).
   A failed read still reports whether the file exists (`App/Sources/System/StatusFeed.swift:17`,
   `App/Sources/System/StatusFeed.swift:50`).
3. **Ping.** At launch and whenever Bench becomes active, Bench posts `dev.ted2xmen.shelf.ping`
   with object `dev.ted2xmen.shelf` (`App/Sources/System/StatusFeed.swift:33`,
   `App/Sources/System/StatusFeed.swift:39-44`, `App/Sources/Model/AppModel.swift:131`). That
   object is Bridge's channel filter: Bridge observes all names but only with that object,
   because macOS does not deliver to a fully unfiltered observer (shelf-bridge
   `Sources/ShelfBridgeCore/Protocol.swift:12-16`, shelf-bridge
   `Sources/ShelfBridgeCore/ShelfChannel.swift:31`). The ping is unsigned and carries nothing. Bridge
   answers it by publishing its status right away, before any signature check, and does nothing
   else with it (shelf-bridge `Sources/ShelfBridgeCore/ShelfChannel.swift:68-69`). See
   [protocol v2, ping](https://github.com/Ted2xmen/shelf-bridge/blob/main/docs/protocol/v2.md#8-ping).

### Merging readings

The file and the notification can arrive in any order. `StatusReader.newer` keeps a status only
when its `seen` is not older than the current one; anything readable beats `unreadable`; any other
case takes the incoming reading (`BenchCore/Sources/BenchCore/Status.swift:35-49`). The model applies
it on every delivery (`App/Sources/Model/AppModel.swift:148`).

### Version check

The version field is decoded first. `v != 2` gives `unsupported(bridge:)`, not `unreadable`
(`BenchCore/Sources/BenchCore/Status.swift:15-24`). The sidebar then shows only the connection line
"Update shelf-bridge" (with Bridge's version when known) and Bench's own sessions
(`BenchCore/Sources/BenchCore/Sidebar.swift:165-168`).

### Link states

`LinkRule.derive` (`BenchCore/Sources/BenchCore/Link.swift:35-46`):

| State | When | Shown |
| --- | --- | --- |
| `looking` | Nothing readable heard yet and less than 5 s since launch (`Link.swift:29`, `Link.swift:43`) | "Looking" line, skeleton rows when there are no sessions (`Sidebar.swift:156-160`) |
| `absent` | After 5 s, nothing readable and no `heartbeat.json` (`Link.swift:44`) | Install footer, sessions and recent folders (`Sidebar.swift:161-164`) |
| `offline` | `seen` older than 180 s, an unparsable `seen`, or a heartbeat file that cannot be read (`Link.swift:31`, `Link.swift:38-39`, `Link.swift:44`) | "Bridge offline · last seen ..." (`Sidebar.swift:169-170`); jobs listed but not live, no Needs you, no limits, This Mac "Unknown" (`Sidebar.swift:182`, `Sidebar.swift:210-211`, `Sidebar.swift:254-257`) |
| `connected` (online) | `seen` within 180 s (`Link.swift:39`) | "shelf-bridge running"; version, last heard and slots in the tooltip (`Sidebar.swift:171-172`) |
| `unsupported` | `v != 2` (`Link.swift:40-41`) | "Update shelf-bridge" (`Sidebar.swift:165-168`) |

Paths in this table are under `BenchCore/Sources/BenchCore/`. Bridge publishes at least every
30 s (shelf-bridge `Sources/ShelfBridgeCore/ShelfChannel.swift:29`, `ShelfChannel.swift:37-39`), so 180 s
covers several missed beats.

A live job's terminal still works when Bridge is offline, because Bench talks to tmux directly
(`BenchCore/Sources/BenchCore/Detail.swift:64-66`).

### Status fields Bench uses

From [status](https://github.com/Ted2xmen/shelf-bridge/blob/main/docs/protocol/v2.md#7-status):

- Top level: `v`, `bridge` (`BenchCore/Sources/BenchCore/Status.swift:17-22`), `seen`
  (`BenchCore/Sources/BenchCore/Status.swift:42`, `BenchCore/Sources/BenchCore/Link.swift:38`),
  `folders` (`BenchCore/Sources/BenchCore/Sidebar.swift:188`, `App/Sources/Model/AppModel.swift:305`),
  `jobs`, `mac`, `limits`, `scheduled` (`BenchCore/Sources/BenchCore/Sidebar.swift:179`,
  `BenchCore/Sources/BenchCore/Sidebar.swift:206-211`).
- Per job: `id`, `title`, `folder`, `agent`, `state`, `started`, `ended`, `now`, `asking`
  (`BenchCore/Sources/BenchCore/Sidebar.swift:235-251`); `ref`, `mode`, `tmux`, `waitingSince`,
  `waitMaxMin`, `out`, `blocked` (`BenchCore/Sources/BenchCore/Detail.swift:56-121`).

Not used anywhere in `App/` or `BenchCore/Sources/`: `keyId`, `paused`, `slots`, and per job
`log`, `attached`, `attachError`. These fields are defined in shelf-bridge
`Sources/ShelfBridgeCore/StatusV2.swift:8-10` and `StatusV2.swift:89-94`. Ended job logs come from
Bridge's log files instead (see "Files and state").

### Mode without Bridge

Bench works without Bridge. With the link `absent`:

- The status bar shows "Autonomous jobs need shelf-bridge" and a copyable install line
  (`BenchCore/Sources/BenchCore/Sidebar.swift:161-162`, `App/Sources/Views/StatusBar.swift:30-31`,
  `App/Sources/Views/StatusBar.swift:127-143`).
- The install line is `brew install --cask ted2xmen/tap/shelf-bridge`
  (`App/Sources/Model/AppModel.swift:322-323`). shelf-bridge has no published cask yet, and the
  existence of the `ted2xmen/tap` tap is UNVERIFIED.
- The sidebar lists folders of Bench's sessions plus recent folders. Recent folders appear in the
  sidebar only in this state (`BenchCore/Sources/BenchCore/Sidebar.swift:135-136`,
  `BenchCore/Sources/BenchCore/Sidebar.swift:145-164`). New session always offers Bridge's
  folders, then recent ones (`App/Sources/Model/AppModel.swift:303-308`).

## Two tmux servers

Bench talks to two separate tmux servers. Both use the same tmux binary: `config.toml [tmux] path`
when set, else the usual places (`App/Sources/System/TmuxRunner.swift:18-22`,
`App/Sources/System/BenchServerRunner.swift:13-15`). Every tmux call is an argv array, never a
shell string (`App/Sources/System/TmuxRunner.swift:41-61`). `TMUX` and `TMUX_PANE` are removed from
the child environment (`App/Sources/System/TmuxRunner.swift:29-35`). Without tmux, jobs show
without a terminal and New session is off (`App/Sources/System/TmuxRunner.swift:11`,
`App/Sources/System/BenchServerRunner.swift:12`).

### 1. Bridge's server (Bridge jobs)

- **Server.** The default tmux server, or `-L <socket>` when `config.toml [tmux] socket` is set
  (`App/Sources/System/TmuxRunner.swift:12-16`, `BenchCore/Sources/BenchCore/Tmux.swift:55-56`).
  `config.toml` is `~/.config/shelf-bridge/config.toml` (shelf-bridge
  `Sources/ShelfBridgeCore/Paths.swift:18-20`). See
  [protocol v2, tmux names](https://github.com/Ted2xmen/shelf-bridge/blob/main/docs/protocol/v2.md#13-tmux-names).
- **Target.** From the job's status `tmux` field, `<session>:<window>`. It is refused unless the
  session name is only `[A-Za-z0-9_-]`, the window equals the job id, and the id is a valid job id
  (`BenchCore/Sources/BenchCore/Tmux.swift:4-22`). The view opens only after a probe finds the job's
  own window (`App/Sources/Model/AppModel.swift:173-185`, `App/Sources/System/TmuxRunner.swift:81-85`).
- **Embedded view.** A grouped session on Bridge's session:
  `new-session -t '=<session>' -s <name> ; set-option destroy-unattached keep-group ;
  set-option detach-on-destroy on ; set-option status off ; select-window -t ':=<id>'`
  (`BenchCore/Sources/BenchCore/Tmux.swift:58-68`). It runs as the tmux client in the pane
  (`App/Sources/Views/DetailView.swift:219-221`). Its name is `view-<id>`, or `view-<id>-<4hex>`
  when a `view-<id>` session is still there (`BenchCore/Sources/BenchCore/Tmux.swift:28-37`,
  `App/Sources/System/TmuxRunner.swift:87-93`).
- **Terminal and copy.** "Open in Terminal" and "Copy tmux command" use the same one-liner under a
  fresh name `term-<id>-<4hex>`, keeping tmux's status bar
  (`BenchCore/Sources/BenchCore/Tmux.swift:31-33`, `App/Sources/System/Files.swift:38-76`).
  Open in Terminal writes a 0700 `.command` file into Bench's own `attach/` folder and opens it with
  Terminal (`App/Sources/System/Files.swift:57-76`).
- **Probes.** Every 2 s each open view is checked; if it no longer shows its job's window, Bench
  marks it closed and closes it before a key reaches the wrong agent
  (`App/Sources/Model/AppModel.swift:23-24`, `App/Sources/Model/AppModel.swift:204-218`,
  `App/Sources/System/TmuxRunner.swift:95-98`). Views of jobs that are no longer live are also
  closed on the next status (`App/Sources/Model/AppModel.swift:150-153`).
- **Kill rule.** Bench kills a session only when its name starts with `view-` and its group size
  is above 1, so the last member (which holds the job windows) is never killed
  (`App/Sources/System/TmuxRunner.swift:100-112`, `BenchCore/Sources/BenchCore/Tmux.swift:119-121`).
  It never kills `shelf-*` sessions and never kills `term-*` sessions. A `term-*` session is left
  to Terminal and tmux's `destroy-unattached keep-group` option.

### 2. Bench's own server (Bench sessions)

- **Server.** Every argv starts with `-L shelf-bench -f <App Support>/Shelf Bench/tmux.conf`
  (`BenchCore/Sources/BenchCore/Sessions.swift:87-106`, `App/Sources/System/Files.swift:19-20`).
  `TMUX_TMPDIR` is also removed so Bench and Open in Terminal reach the same socket
  (`App/Sources/System/BenchServerRunner.swift:18-24`).
- **Names.** `bench-` plus 8 lower-case hex digits; the only names Bench makes, reads or kills on
  this server (`BenchCore/Sources/BenchCore/Sessions.swift:44-57`). Every Bridge call checks the name
  first (`App/Sources/System/BenchServerRunner.swift:57-79`).
- **Options.** Each new session gets `@bench_agent` and `@bench_folder`
  (`BenchCore/Sources/BenchCore/Sessions.swift:112-118`). `list-sessions` lines without a valid name,
  a known agent and an absolute folder are skipped
  (`BenchCore/Sources/BenchCore/Sessions.swift:204-216`).
- **Conf.** Written on every launch and sourced into a running server
  (`App/Sources/System/BenchServerRunner.swift:42-49`, `BenchCore/Sources/BenchCore/Sessions.swift:108-110`).
  It turns off the status line and the prefix keys, unbinds the right-click menus, keeps the server
  alive when empty, keeps dead panes (`remain-on-exit on`), sets 50000 lines of history,
  `tmux-256color`, RGB and extended keys, mouse on and `pbcopy` as copy command
  (`BenchCore/Sources/BenchCore/Sessions.swift:145-173`). A test checks the key lines
  (`BenchCore/Tests/BenchCoreTests/SessionTests.swift:69-77`).
- **Agent argv.** `<login shell> -l -c 'exec "$@"' bench claude` or `... bench codex`; a shell
  session is `<login shell> -l` (`BenchCore/Sources/BenchCore/Sessions.swift:76-84`). The login shell
  is `$SHELL` when it is an absolute zsh, bash, sh or ksh, else `/bin/zsh`
  (`BenchCore/Sources/BenchCore/Sessions.swift:63-74`, `App/Sources/System/BenchServerRunner.swift:35-36`).
  There is no print mode and no permission bypass flag. A test bans
  `--dangerously-skip-permissions`, `--yolo`, `--full-auto`,
  `--dangerously-bypass-approvals-and-sandbox`, `-p`, `--print` and a bare `exec` word, and requires
  at least two words (`BenchCore/Tests/BenchCoreTests/SessionTests.swift:52-59`).
- **Respawn and kill.** Restart is `respawn-pane -k` on the session's pane; End is `kill-session`
  on the exact name (`BenchCore/Sources/BenchCore/Sessions.swift:125-128`,
  `App/Sources/System/BenchServerRunner.swift:65-73`). End asks first unless the pane is dead or
  runs an idle shell (`BenchCore/Sources/BenchCore/Sessions.swift:218-223`,
  `App/Sources/Model/AppModel.swift:268-272`). Bench never runs `kill-server` (no occurrence in
  `App/` or `BenchCore/Sources/`). Quitting Bench leaves these sessions running; only job views are
  closed (`App/Sources/Model/AppModel.swift:135-139`).
- **Embedded client.** `attach-session -t =<name>` in the pane
  (`BenchCore/Sources/BenchCore/Sessions.swift:122-123`, `App/Sources/Views/DetailView.swift:199-201`).
  Open in Terminal writes a `.command` that unsets `TMUX TMUX_PANE TMUX_TMPDIR` and execs the same
  attach (`BenchCore/Sources/BenchCore/Sessions.swift:138-143`,
  `App/Sources/System/BenchServerRunner.swift:85-102`).

## Needs you and asking

- **Job asking** comes from Bridge: the status job's `asking` field. A job row asks only when
  online, live (`running` or `stalled`) and `asking` is true
  (`BenchCore/Sources/BenchCore/Sidebar.swift:249-250`, `BenchCore/Sources/BenchCore/Words.swift:57-58`).
- **Session asking** reuses Bridge's rule on Bench's own captured screen.
  `SessionAsking.isAsking` takes the last 12 non-blank lines and calls Bridge's
  `JobSummary.asking` with `mode: "attended"`, `state: "running"` and the quiet time
  (`BenchCore/Sources/BenchCore/Sessions.swift:237-243`). Bridge's rule needs an attended active
  job, at least 60 s of quiet, and a last line ending in `?` or a known prompt phrase
  (shelf-bridge `Sources/ShelfBridgeCore/Limits.swift:206-212`,
  [source at the pinned revision](https://github.com/Ted2xmen/shelf-bridge/blob/f815abd57072efef572f5244cee62b7ae1bd3866/Sources/ShelfBridgeCore/Limits.swift#L206-L212)).
  Shell sessions and dead panes never ask (`BenchCore/Sources/BenchCore/Sessions.swift:239`).
- **Quiet time** is now minus tmux's `window_activity`
  (`BenchCore/Sources/BenchCore/Sessions.swift:92-93`, `BenchCore/Sources/BenchCore/Sessions.swift:210-214`).
- **Capture gate.** Bench captures a pane (`capture-pane -p -J -S -12`) only when the session is
  live, quiet for 60 s, and its activity changed since the last look
  (`BenchCore/Sources/BenchCore/Sessions.swift:228-235`, `BenchCore/Sources/BenchCore/Sessions.swift:131`,
  `App/Sources/Model/AppModel.swift:233-238`). A session found asking stays asking while it stays
  quiet and alive (`App/Sources/Model/AppModel.swift:233`).
- **Needs you scope** for jobs: first-run approval, failed, `waiting:signature`, or live and asking.
  `stalled` alone is not in it (`BenchCore/Sources/BenchCore/Sidebar.swift:224-233`). Needs you is
  empty when Bridge is offline (`BenchCore/Sources/BenchCore/Sidebar.swift:181-182`). Asking Bench
  sessions are listed in Needs you too (`BenchCore/Sources/BenchCore/Sidebar.swift:106-107`,
  `BenchCore/Sources/BenchCore/Sidebar.swift:142`).
